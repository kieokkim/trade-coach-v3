## 왜 만들었나

유튜브로 트레이딩을 독학하면서 한 가지 문제를 발견했습니다.
혼자 공부하면 배울 수 있지만, 내가 제대로 하고 있는지
피드백해줄 사람이 없습니다.

ICT(Inner Circle Trader) 기술적 분석은 감이 아니라
근거에 의한 트레이딩을 강조합니다.
FVG, Order Block, 킬존 같은 개념들은
진입 근거를 명확히 설명할 수 있어야 제대로 된 트레이딩입니다.

> "왜 여기서 들어갔어?"
> "FVG가 있었고, 킬존이었고, OB 재테스트가 있었어."

ICT는 rule-based 분석이기 때문에 AI 코칭이 가능합니다.
TradeCoach는 이 아이디어에서 시작했습니다.

## 코칭의 관점에서

TradeCoach는 세 가지 질문에 답합니다.

**1. 지금 내 트레이딩 실력은?**
승률·수익률·손절 일관성을 수치가 아닌 행동 패턴으로 해석합니다.

**2. 그때 내 진입은 옳았나?**
진입 시점 캔들을 복원하고 A+ 채점으로
"구조는 맞았는데 킬존을 놓쳤다"처럼 구체적 피드백을 줍니다.

**3. 같은 실수를 반복하고 있나?**
세션마다 약점을 누적 추적하고
내일 당장 실행할 수 있는 규칙 1개를 제시합니다.

## 핵심 기능

### 1. 거래내역 자동 분석
- Bybit V5 API 자동 수집 (없으면 샘플 데이터)
- KPI 4가지: 승률 / 평균 수익률 / 수익금 / 손절 일관성
- ICT 기반 약점 자동 태깅
  (과매매_감지 / 킬존외_진입 / 손절_불규칙 등)

### 2. 거래 복기 뷰어 (Trade Context Viewer)
- Bybit Kline API로 진입 시점 캔들 복원
- FVG / Order Block / 추세선 / 채널 rule-based 탐지
- plotly 캔들차트 + 진입/청산 마커 + ICT 오버레이

### 3. A+ 채점 시스템
ICT 이론 기반 5가지 기준 자동 채점:
- 구조 진입: 진입가가 FVG/OB 구간 내
- 반등 확인: 직전 캔들이 구조 레벨에서 지지
- 추세 정렬: 진입 방향과 추세선 일치
- 킬존 진입: 런던/뉴욕 세션 시간대
- 손절 규율: 당일 손절 3회 미만

### 4. 캔들 기반 진입 근거 자동 추론
캔들 데이터 + ICT 패턴을 LLM에 넘겨
"왜 이 시점에 진입했는가"를 자동 추론하고
개선 코칭을 제공합니다.

### 5. AI-as-Judge 코칭 검수
backtest_coach가 생성한 코칭 결과를
별도 LLM이 트레이딩 철학 5가지로 자동 검수합니다.
- 하루 3번 손절 시 거래 중단 언급 여부
- 최대 손실금액 고정 언급 여부
- Revenge Trading 경고 포함 여부 등

### 6. 세션 메모리
- SQLite 기반 약점 태그 누적 저장

```
# FVG/OB/추세선 rule-based 탐지
→ entry_reason_node  # A+ 채점 + LLM 진입 근거 추론
→ replay_coach       # LLM 복기 코멘트
→ UI 표시
```

## 엔지니어 클럽을 진행하며 느낀 점

**Rule-based와 LLM의 역할 분리가 핵심이었습니다.**
ICT 패턴 탐지(FVG/OB/추세선)는 rule-based로,
코칭과 추론은 LLM으로 분리했더니 결과의 일관성과
신뢰도가 크게 높아졌습니다.

**DECISION_LOG가 장기 프로젝트의 생명선입니다.**
"왜 이렇게 설계했는가"를 기록해두지 않으면
몇 주 후에 같은 실수를 반복하게 됩니다.
설계 결정을 문서화하는 습관이 코드 품질만큼 중요합니다.

**Claude Code와의 협업에서 프롬프트 품질이 코드 품질을 결정합니다.**
막연하게 "만들어줘"보다 완료 기준(DoD)을 명시하고,
CLAUDE.md에 프로젝트 원칙을 정리해두면
일관성 있는 결과물을 얻을 수 있습니다.

**데모 시나리오 설계가 기능 구현만큼 중요합니다.**
초보/중급/고수 트레이더 시나리오를 만들면서
"이 에이전트가 실제로 무엇을 해야 하는가"가
더 명확해졌습니다.

조사 항목
1. 결함 1/9 — get_candles의 "실패 vs 데이터 없음" 미구분

market/candles.py::get_candles와 nodes/fetch_nodes.py::bybit_fetch_node를 보고:

먼저: TC-D37이 이 두 함수에 정확히 뭘 바꿨는지 diff나 git log로 확인 (git log -p --follow -- nodes/fetch_nodes.py 등). sample_mode 분기가 이제 어디서 먼저 체크되는지 파악한 뒤, 그 변경이 아래 문제에 영향을 주는지 판단.
거래소 API 호출이 실패했을 때(키 없음/만료/네트워크 예외)와, 호출은 성공했으나 데이터가 0건일 때가 코드상 어디서 갈라지는지 — 혹은 안 갈라지고 한 분기로 합쳐지는지 정확한 라인으로 특정 (TC-D37 이후 현재 상태 기준).
더미 캔들(_generate_dummy_candles) 자동 대체가 정확히 어떤 조건에서 발동하는지, 그 조건이 "데모 모드 플래그"와 연동되는지 아니면 실거래 경로에서도 무조건 발동하는지.
api/main.py의 if not candles: raise HTTPException(404)가 왜 도달 불가능한지 (더미 대체가 그 앞에서 항상 비어있지 않은 배열을 만들어서인지) 코드 흐름으로 확인.
결론: 이 결함을 고치려면 (a)더미 대체를 데모 플래그로 격리 (b)실패/빈데이터 분기 신설 중 무엇이 필요한지, 건드릴 파일·함수 목록.
2. 결함 4/10 — journal_entries 테이블 부재 + A+ 손절규율 기준

nodes/entry_reason_node.py::score_aplus의 "손절 규율" 기준(:92-101 부근)과 db.py::init_db, 그리고 docs/05_MVP_DB_스키마_설계서* 문서를 대조해서:

journal_entries 테이블이 원래 어떤 설계였는지 (설계서에 스키마가 있는지, 어떤 컬럼을 기대하는지). CREATE가 누락된 건지, 애초에 설계만 있고 구현 안 된 건지.
A+ 손절규율 기준이 이 테이블 없이 다른 데이터로 판정 가능한지 — 예를 들어 trade_history나 다른 테이블에 손절 관련 정보가 있는지, 아니면 이 테이블이 유일한 소스인지.
현재 except Exception: bd["stop_discipline"]=True가 로그도 없이 항상 True를 반환하는 그 지점을, "미채점(unscored)"으로 바꾸려면 반환 구조를 어떻게 바꿔야 하는지 (score_aplus 반환 dict의 형태, 이걸 소비하는 쪽 코드 위치).
결론: (a)테이블 CREATE만 추가하면 되는지 (b)기준 로직 자체를 재설계해야 하는지 권고. 목업 v7이 이 기준을 "데이터 없음"으로 정직 표시하기로 한 것과 일치시키는 방향으로.
3. 백엔드 /replay 응답의 존 발생시각 포함 여부

api/main.py의 /replay/candles, /replay/aplus 응답과, 그 안에서 호출하는 ict/fvg_detector.py·ict/ob_detector.py의 반환 구조를 보고:

탐지된 각 FVG/OB 존이 **발생 시각(생성 캔들의 timestamp)**을 반환값에 담고 있는지, 아니면 가격 범위(low/high)만 담고 시각은 버리는지.
UI에서 존이 "차트 왼쪽 끝부터 전체 폭에 그려지던" 버그(감사 항목3 연관)가, 프론트가 시각을 안 쓴 문제인지 / 백엔드가 시각을 애초에 안 준 문제인지 확정.
결론: UI 세션에서 존을 발생시각부터 렌더하려면 백엔드 응답을 손봐야 하는지, 아니면 이미 시각이 있어서 프론트만 고치면 되는지.
